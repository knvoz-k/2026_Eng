# EC_Car

基于 `STM32F407VET6` 的智能车控制工程，面向工程竞赛中的自主移动、视觉识别、越障、排爆、打靶和人质救援等任务。

当前仓库主要完成了底层硬件初始化、双路电机 PWM 控制、双路编码器里程统计、MaixCAM 串口通信和基础任务状态机框架。完整比赛流程仍在持续开发中。

## 功能概览

- STM32F407VET6 主控，Cortex-M4，系统时钟配置为 168 MHz
- 基于 STM32 HAL 的外设驱动
- TIM1 四路 PWM 控制左右电机正反转
- TIM4、TIM5 编码器接口读取左右轮脉冲
- TIM7 每 10 ms 触发一次编码器采样和距离控制
- USART1 接收前置 MaixCAM 数据
- USART2 接收侧置 MaixCAM 数据
- UART5 提供 `printf` 调试输出
- PE2 外部中断按键启动任务

## 工作流程

系统启动后，`main()` 依次初始化 GPIO、DMA、串口、PWM、编码器和 TIM7 定时器，然后进入主循环。

```text
上电
  │
  ├─ 初始化 MaixCAM DMA 接收
  ├─ 初始化左右编码器
  ├─ 启动电机 PWM
  ├─ 启动 TIM7 10 ms 中断
  │
  └─ 主循环
       ├─ 检查启动按键请求
       └─ 执行 car_task_run()
```

TIM7 中断每 10 ms 执行：

1. 读取 TIM4/TIM5 当前周期内的编码器脉冲。
2. 计算左右轮速度并累加左右轮距离。
3. 执行 `control_run_10ms()`。
4. 当平均距离达到目标值时停止电机。

直行控制目前采用分段 PWM：

| 距离目标的剩余距离 | 左右电机 PWM |
| --- | ---: |
| 大于 100 | 1000 |
| 60 至 100 | 800 |
| 30 至 60 | 400 |
| 小于 30 | 200 |
| 达到目标 | 0 |

## MaixCAM 通信协议

所有串口通信均配置为：

- 波特率：`115200`
- 数据位：8
- 停止位：1
- 校验：无
- 流控：无

### 前置摄像头：USART1

前置摄像头数据帧格式：

```text
#f data1 data2 data3 #e
```

例如：

```text
#f 1 2 3 #e
```

解析成功后，数据写入 `maixcam_front`：

- `data1`：任务相关数据，例如炸弹颜色
- `data2`：任务相关数据，例如目标颜色
- `data3`：任务相关数据，例如人质类型
- `valid`：新数据有效标志

### 侧置摄像头：USART2

侧置摄像头数据帧格式：

```text
#s red_x green_x blue_x red_y green_y blue_y #e
```

例如：

```text
#s 10 20 30 40 50 60 #e
```

解析成功后，数据写入 `maixcam_side`，分别保存红、绿、蓝目标的 `x/y` 坐标和 `valid` 标志。

接收采用 `HAL_UARTEx_ReceiveToIdle_DMA()`，单帧缓冲区大小为 128 字节，并关闭 DMA 半传输中断。

## 关键硬件映射

以下信息来自 `EC_Car.ioc` 和 CubeMX 生成的初始化代码。

| 功能 | 外设/引脚 |
| --- | --- |
| 左电机方向/PWM | TIM1 CH1/CH2，PE9/PE11 |
| 右电机方向/PWM | TIM1 CH3/CH4，PE13/PE14 |
| 左编码器 | TIM4 CH1/CH2，PD12/PD13 |
| 右编码器 | TIM5 CH1/CH2，PA0/PA1 |
| 启动按键 | PE2，下降沿 EXTI2 |
| 前置 MaixCAM | USART1，PA9/PA10 |
| 侧置 MaixCAM | USART2，PA2/PA3 |
| 调试日志 | UART5，PC12/PD2 |
| 预留串口 | USART6，PC6/PC7 |
| 周期控制中断 | TIM7，10 ms |

电机控制使用 TIM1 的四路互补式 PWM 映射：

```text
左侧：  CH1 = 中点 + PWM1
        CH2 = 中点 - PWM1

右侧：  CH3 = 中点 + PWM2
        CH4 = 中点 - PWM2
```

PWM 计数周期为 `8400`，`motor_load()` 会将输入限制在半周期范围内。

## 构建环境

### 推荐工具

- STM32CubeMX 6.18.0
- STM32Cube FW_F4 V1.28.3


仓库同时包含：

- `MDK-ARM/EC_Car.uvprojx`：Keil MDK 工程
- `EC_Car.ioc`：STM32CubeMX 配置


## Keil MDK 构建

1. 使用 Keil MDK 打开 `MDK-ARM/EC_Car.uvprojx`。
2. 检查目标器件是否为 `STM32F407VETx`。
3. 根据开发板连接情况配置下载器和调试器。
4. 选择目标配置并执行 Build/Rebuild。
5. 使用 Keil 的 Download 功能烧录到目标板。

仓库中的 `MDK-ARM/EC_Car/` 包含若干历史编译产物，例如 `.hex`、`.axf`、`.map` 和目标文件。这些文件适合用于定位已有构建结果，不建议将它们当作源码修改入口。

## 调试输出

工程通过重定向 `fputc()` 将 `printf()` 输出到 UART5。常见日志包括：

```text
[TASK] Starting CAR_STATE_MOVE_TO_QRCODE
pulse_left: ..., pulse_right: ..., speed_left: ..., speed_right: ...
```

连接 UART5 后，可使用任意串口工具以 `115200 8N1` 查看日志。

## 已知限制和后续工作

- 任务状态机仍有多个空状态，越障、抓取、激光和救援执行器尚未接入。
- 当前直行控制为简单分段 PWM，没有 PID、转向补偿或速度闭环。
- 编码器距离计算依赖 `BSP/encoder.c` 中的轮半径和每圈脉冲数，实际单位和机械标定需要结合硬件确认。
- 左右轮方向、编码器正负方向和电机接线需要在实车上验证。
- 前置协议字段目前只保存为通用的 `data1/data2/data3`，具体颜色和任务编码需要与 MaixCAM 端约定。
- 侧置摄像头数据已解析，但当前任务状态机尚未消费这些坐标。
- USART6 已完成初始化，但当前应用层没有使用它。
- `car_task_run()` 中部分移动状态仍处于基础框架阶段，执行前应结合目标硬件验证状态切换和控制调用时机。
- 当前仓库未提供自动化单元测试或硬件在环测试。

## 开发建议

- 修改 CubeMX 外设配置后，优先检查 `Core/Src` 和 `Core/Inc` 的生成结果，再编译验证。
- 应用逻辑放在 `APP/`，硬件封装放在 `BSP/`，尽量避免在任务状态机中直接操作 HAL 外设句柄。
- 调整电机控制前，先抬起车轮进行 PWM 极性、左右轮方向和急停验证。
- 调整编码器参数前，使用日志记录实际脉冲数、轮速和累计距离。
- 修改 MaixCAM 协议时，同时更新发送端、`BSP/maixcam.c` 的解析格式和联调说明。
